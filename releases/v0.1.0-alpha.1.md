# v0.1.0-alpha.1 — OIDC publish verification

## TL;DR

First publish via GitHub Actions + OIDC Trusted Publisher. **No functional change from `0.1.0-alpha.0`** — this release exists to validate the CI/CD pipeline end-to-end.

If you see a green `publish.yml` run on this tag, the autopilot is live. From `0.1.0-alpha.2` onward, releases become a non-event: bump version + write narrative + tag + push.

## Why this release exists

`0.1.0-alpha.0` was published manually from a local terminal with `--no-provenance` override. The `publishConfig.provenance: true` setting requires an OIDC token that a bare shell can't produce — there's no GitHub Actions runner to mint the JWT, so npm errored with `Automatic provenance generation not supported for provider: null`.

This release wires up the proper path:

1. Push tag `v0.1.0-alpha.1`
2. `publish.yml` fires on `push: tags: ['v*']`
3. `build` job: `setup-node@v4 node 22` (no `registry-url` per `actions/setup-node#1440` poisoning OIDC) → `npm ci` → `npm run build` → `npm test` → `npm pack --dry-run`
4. `release` job: verifies `releases/v0.1.0-alpha.1.md` exists → `gh release create --notes-file` reads this file verbatim
5. `publish` job: `id-token: write` mints an OIDC JWT → `npm` exchanges JWT against the Trusted Publisher config on npmjs.com → publishes with SLSA provenance attestation
6. Dist-tag routing: version contains `-alpha.` → tagged `next` on npm (not `latest`, so `npm install @luutuankiet/write-pr` still pins to the most recent stable when there is one)

## Highlights

| Capability | What it does | Why it matters |
|---|---|---|
| OIDC Trusted Publisher | Zero secrets in GitHub repo; npmjs.com verifies the workflow identity directly | No `NPM_TOKEN` to rotate; supply chain auditable |
| SLSA provenance | `npm publish --provenance` attaches signed build attestation | Visible on the npm package page as a green Sigstore badge |
| Tag-vs-package.json verify | Build job's first step fails fast if `vX.Y.Z` tag doesn't match `package.json` version | Catches forgotten version bumps before any irreversible action |
| `releases/vX.Y.Z.md` gate | Release job aborts if the narrative notes file is missing | Forces hand-written release notes; no empty stubs |
| Dist-tag routing | `-dev.*` → `dev`, `-(rc\|beta\|alpha).*` → `next`, else `latest` | Pre-release channels isolated from `npm install pkg` |

## Hard truth

If this run fails, the most likely causes (in descending order):

1. **npmjs.com Trusted Publisher config drift** — wrong workflow filename (`publish.yml`), wrong repo (`luutuankiet/write-pr`), or an Environment value populated when it should be blank.
2. **`setup-node` regression** — if `registry-url` snuck back into either job, OIDC auth gets poisoned by the placeholder `NODE_AUTH_TOKEN`.
3. **`npx -y npm@latest`** — swapped for `npm install -g npm@latest` which breaks on Node 22.22.2 with `MODULE_NOT_FOUND promise-retry`.

If any of those triggered, the `publish` job logs will say exactly which.
