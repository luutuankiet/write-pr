# v0.2.1 — quality-bar describe layer

Docs / skill-content patch — no code change, no breaking change.

NEW `rules/good-pr-traits.md`: 7 quality traits a good PR has — spoon-feed evidence inline (incl. mermaid diagrams for topology / state / flow), resolve private context (symbolic + verbal forms), collapse at section boundary (every `##` wrapped in `<details>` since GitHub PR view has no TOC), anchor prior-runs to a reproducible ID, text-fallback for auth-gated links, hypothesis-vs-evidence tag, file:line citations carry line ranges. Framed as DESCRIBED traits, not enforced template — the agent picks the structure that fits the change.

README rewritten around the code-execution value prop (rich PR = 15-50 KB of agent context burned passing raw evidence through; write-pr inverts that via the disk-evidence + render-once pattern). Adds 4 worked use cases (perf regression / schema migration / CI failure / fold appendix), a new "What makes a good PR" section surfacing the trait taxonomy, plus npm / CI / SLSA badges.

`SKILL.md` and `workflow.md` cross-reference good-pr-traits.md as READ-FIRST. `callout-gotcha.md` notes the Trait 3 interaction (GitHub `[!TIP]` callouts must be OUTSIDE the per-h2 `<details>` wrap, otherwise they render as plain quoted text).

Install: `npx -y @luutuankiet/write-pr@latest install-skill` picks up the new rule doc automatically. Tarball: 35 → 36 files.
